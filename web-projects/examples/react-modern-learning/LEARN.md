# React Modern Learning 学习说明

这份文档讲的是“怎么学这套页面”，重点不是死记 React API，而是把每一章放进企业开发场景里理解。

> 最新的源码导读请优先看 [FRONTEND_LEARNING_GUIDE.md](./FRONTEND_LEARNING_GUIDE.md)，页面右侧的 `Learning Panel` 也会同步展示运行时 Trace。

## 总体学习方法

先看页面效果，再看组件，再看状态和事件，最后回到源码和测试。

不要先背 API 名称，要先回答这些问题：

- 这个页面解决什么业务问题
- 状态为什么要放在这里
- 路由为什么要拆成这样
- 和后端是怎么配合的
- 测试到底在验证什么

### 企业开发中的作用

企业后台首页通常负责：

- 展示模块入口

- 作为导航中枢

### 和后端如何协作

首页通常不直接承载复杂接口，而是负责把用户带到具体业务页面。

### 下一章

`Hooks`

## 2. Hooks

### 本章目标

理解 `useState`、`useEffect` 和状态更新的基本方式。

### 为什么学习

React 的核心不是“写页面”，而是“管理会变化的数据”。

### React 官方知识

学习：

- `useState`
- `useEffect`
- 事件处理
- 清理函数
- 派生状态

### 企业开发中的作用

Hooks 在企业里最常见的用途是：

- 页面状态
- 输入框
- 分页
- Loading
- Modal
- Form
- Task 创建
- 搜索条件

为什么不用普通变量：

- 普通变量不会触发视图更新
- 普通变量不会在重渲染后保持一致的 UI 状态
- 普通变量无法表达副作用和生命周期

### 和后端如何协作

Hooks 经常负责管理请求前后的页面状态，比如：

- 发起请求前显示 Loading
- 请求成功后更新列表
- 请求失败后显示错误
- 表单提交后刷新数据

### `Retail Insight AI` 对应位置

对应 `Task`、`State`、`Create`、`Report` 这些交互环节。

### 学习完成后你应该掌握什么

- 知道状态为什么要用 Hook 管理
- 能区分渲染值和普通变量
- 能看懂副作用和清理逻辑

### 下一章

`Router`

## 3. Router

### 本章目标

理解路由如何把一个 React 应用组织成多个业务页面。

### 为什么学习

企业系统不是一个页面，而是一组可切换的业务页面。

### React 官方知识

学习：

- `NavLink`
- `Outlet`
- 嵌套路由
- 动态参数

### 企业开发中的作用

Router 在企业里几乎是必需品，常见场景包括：

- 后台管理系统
- 菜单导航
- 详情页
- 用户中心
- 权限页面
- 审批页面

为什么企业一定需要 Router：

- 页面数量多
- 功能模块多
- 需要深链接
- 需要浏览器前进后退
- 需要按权限控制访问

### 和后端如何协作

路由通常对应后端接口所服务的不同业务域，例如：

- 列表页
- 详情页
- 编辑页
- 审批页

### `Retail Insight AI` 对应位置

对应 `Dashboard`、`Documents`、`Approval`、`RAG` 等业务路径。

### 学习完成后你应该掌握什么

- 知道路由为什么存在
- 能看懂嵌套路由
- 能理解页面和子页面的关系

### 下一章

`Context`

## 4. Context

### 本章目标

理解全局共享状态如何通过 Context 传递。

### 为什么学习

有些数据不是某一个组件独有的，而是整个页面树都要用。

### React 官方知识

学习：

- `createContext`
- `Provider`
- `useContext`

### 企业开发中的作用

Context 常用于：

- 登录用户
- `JWT`
- `Token`
- `RBAC`
- 主题
- 国际化
- 全局配置

为什么 Context 不等于数据库：

- Context 只是在前端组件树中共享数据
- 它不负责持久化
- 它不负责业务存储
- 它不负责替代后端状态

### 和后端如何协作

后端返回用户信息、权限信息和配置数据后，前端经常把它们放入 Context，供整个页面树使用。

### `Retail Insight AI` 对应位置

对应当前项目里的主题切换，以及未来的登录态、权限和配置。

### 学习完成后你应该掌握什么

- 知道 Context 适合共享什么
- 知道 Context 不适合替代什么
- 能理解跨层传值的必要性

### 下一章

`API`

## 5. API

### 本章目标

理解 React 如何通过 HTTP 和后端系统协作。

### 为什么学习

API 不是学习 `fetch()` 本身，而是学习前端如何接入真实业务系统。

### React 官方知识

学习：

- 请求发起
- `loading` 状态
- `error` 状态
- `success` 状态
- 请求取消

### 企业开发中的作用

API 章节真正要理解的是这一条链路：

```text
React
↓
HTTP
↓
FastAPI / Spring Boot
↓
JSON
↓
页面刷新
```

真实企业请求流程通常是：

```text
React
↓
Axios / fetch
↓
REST API
↓
Service
↓
Repository
↓
Database
```

### 和后端如何协作

前端负责：

- 发起请求
- 组装参数
- 处理返回值
- 更新界面

后端负责：

- 验证请求
- 执行业务逻辑
- 访问数据库
- 返回结构化 JSON

### `Retail Insight AI` 对应位置

`Documents`、`Tasks`、`Approval`、`RAG` 都属于同一类请求流程。

### 学习完成后你应该掌握什么

- 知道 API 章节不是只学 `fetch`
- 能看懂前后端请求链路
- 能区分前端渲染和后端业务

## 6. Test

### 本章目标

理解为什么企业项目必须写测试，以及前端测试和后端测试如何一起工作。

### 为什么学习

只靠手动点击无法支撑企业项目的长期演进。

### React 官方知识

学习：

- 组件测试
- 用户行为测试
- 断言
- 测试文件配对

### 企业开发中的作用

企业必须写测试，因为：

- 页面经常改
- 业务逻辑经常变
- 回归风险高
- 多人协作容易引入问题
- CI 需要自动验证

测试通常分为：

- Frontend Test
- Backend Test
- CI 自动验证

### 和后端如何协作

前端测试保证交互不会坏，后端测试保证业务逻辑不会坏，CI 负责把它们统一跑起来。

### `Retail Insight AI` 对应位置

对应整个系统的回归验证层，尤其是表单、审批、流程和数据展示相关场景。

### 学习完成后你应该掌握什么

- 知道为什么测试是企业刚需
- 能理解组件测试的价值
- 能把测试和 CI 联系起来

## 7. Learning Trace

### 本章目标

理解页面右侧的 `Learning Panel` 如何帮助你从运行时回到源码。

### 为什么学习

很多初学者只会看源码，不会把源码和页面行为对应起来。

### React 官方知识

学习运行时渲染、组件树、事件触发和状态变化的关系。

### 企业开发中的作用

Trace 能帮助你在复杂系统里快速定位：

- 哪个组件重渲染了
- 哪个状态变了
- 哪个请求触发了
- 哪个测试文件对应当前组件

### 和后端如何协作

当接口返回变化时，Trace 可以帮助你快速确认是前端状态问题还是后端数据问题。

### `Retail Insight AI` 对应位置

对应运行时调试和业务排障。

### 学习完成后你应该掌握什么

- 会从页面回看源码
- 会从 Trace 找到状态变化
- 会把 UI 行为和代码关联起来

## 学习完成后的整体理解

学完以后，你应该形成下面这套认知：

- `State`、`Props`、`Hook`、`Router`、`Context`、`API`、`Test` 不是孤立知识点
- 它们共同组成企业 React 架构
- 前端不是只负责“显示”
- 前端还负责“组织页面、管理状态、调用后端、验证行为”

## 学习建议

不要死记 React API。

要先理解：

- 为什么有 `State`
- 为什么有 `Props`
- 为什么有 `Hook`
- 为什么有 `Router`
- 为什么有 `Context`
- 为什么有 `API`
- 为什么有 `Test`

它们共同组成企业 React 架构。
