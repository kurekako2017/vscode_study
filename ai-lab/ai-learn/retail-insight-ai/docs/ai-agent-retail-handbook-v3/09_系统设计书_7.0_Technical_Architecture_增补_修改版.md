# 7.1 Framework Responsibilities（框架职责说明）

本章回答：**每一个技术框架在 ERIP 中负责什么？**

| 技术                         | 中文说明               | 在本项目中的职责                                                    |
| ---------------------------- | ---------------------- | ------------------------------------------------------------------- |
| React                        | 前端展示层             | 提供经营分析页面、任务创建、SSE 实时状态展示、报告查看。            |
| FastAPI                      | HTTP 边界              | 提供 REST API、参数校验、认证入口，不直接编排业务流程。             |
| Task API                     | 接口层                 | 提供统一的 Task 创建、查询、事件与报告接口。                        |
| TaskService                  | 应用服务层             | 管理 Task 生命周期，协调 Workflow、Repository 与 Report Generator。 |
| LangGraph                    | Workflow Orchestration | 管理 State、Node、Edge、Checkpoint，是 AI Workflow 状态机。         |
| Fixed KPI Workflow           | KPI 分析流程           | 基于业务数据计算固定 KPI，不依赖 LLM。                              |
| Research Agent               | 调研代理               | 调用搜索与内部知识，生成 Research 结果。                            |
| LangChain（Planned）         | RAG 编排层             | 管理 Retriever、Prompt Builder、Context Builder、Tool Calling。     |
| Repository Pattern           | 数据访问抽象           | 隔离业务逻辑与数据库实现。                                          |
| SQLite（Current）            | 当前数据库             | 当前默认持久化实现。                                                |
| PostgreSQL（Target）         | 企业数据库             | 企业级持久化与事务支持。                                            |
| pgvector（Target）           | 向量数据库扩展         | 存储 Embedding，支持语义检索。                                      |
| Keyword Retrieval（Current） | 关键词检索             | 当前文档检索方式。                                                  |
| Embedding（Planned）         | 向量化                 | 将文档转换为向量。                                                  |
| Hybrid Retrieval（Target）   | 混合检索               | Keyword + Vector 检索。                                             |
| Rerank（Target）             | 重排序                 | 提高检索结果质量。                                                  |
| Context Builder              | 上下文构建             | 合并 KPI、Research 与 RAG 上下文。                                  |
| Report Generator             | 报告生成               | 输出最终日文经营分析报告。                                          |
| SSE                          | 实时推送               | 推送任务状态。                                                      |
| Redis（Target）              | 缓存                   | 热数据与状态缓存。                                                  |
| RabbitMQ（Target）           | 消息队列               | 异步任务与解耦。                                                    |
| Docker（Current）            | 容器化                 | 保证开发部署一致。                                                  |
| Kubernetes（Target）         | 容器编排               | 企业级部署与扩缩容。                                                |
| OpenTelemetry（Target）      | 可观测性               | Trace、Metrics、Logs。                                              |

## TL Review 会关注什么

介绍每个框架时建议统一按照以下顺序：

1. Responsibility（负责什么）
2. Design Rationale（为什么采用）
3. Collaboration（上下层如何协作）
4. Current（当前实现）
5. Planned / Target（未来演进）

这样既符合系统设计文档，也符合日本企业 TL Review 的表达方式。
