## 第一章 知识服务于企业交付

ERIP 是真实企业交付的零售经营智能平台，是真实企业交付项目（不是学习/练习/Demo 项目）。知识点必须能映射到：

```text
登录/JWT/RBAC
→ 文書管理（Upload / Import / Chunk）
→ RAG検索 / Citation
→ 显式 AI分析（low_cost）
→ 生成取締役会报告（high_quality）
→ Report / ReportVersion
→ 提交 Approval
→ manager 审批
→ Persistent Audit
→ LLM Usage Ledger
```

## 第五章 RAG 与 Citation

### 普通 RAG（Internal RAG）

- 在 Document Retrieval 之上组装 grounded answer。
- 默认路径**不调用真实付费 LLM**；deterministic / extractive 合成 + Citation。
- 可要求 citations；证据不足则业务拒绝，而不是胡编。

### 与显式 AI 分析的边界

| 路径 | 是否默认调 Gateway | 费用 | 用途 |
|---|---|---|---|
| Retrieval / Internal RAG | 否 | 零（默认） | 检索与引用回答 |
| AI 分析 `POST /api/v1/ai-analysis` | 是（low_cost） | 受 Ledger 约束 | 显式确认后的分析 |
| 董事会报告 | 是（high_quality） | 受 Ledger 约束 | 経営会议报告 |

【为什么这样设计】

经营会议要根拠。普通检索应低成本、可审计；只有用户显式确认才进入可能收费的 AI 路径。

【源码映射】


## 第六章 LLM Gateway 与双路由

### 技术版本（本章）

| 项 | 版本/标识 | 来源 |
|---|---|---|
| httpx | **0.28.1** | requirements（Provider 出站） |

| Runtime 表 | `ai_runtime_settings` | Alembic **`20260717_08_ai_runtime`** |
| 金额类型 | Decimal（禁止 float） | Ledger / Operation Policy |
| Fallback | OpenRouter→NVIDIA→Gemini→Local Qwen | `provider_chain.py` |

### Gateway 唯一入口

`LLMGatewayService` 是唯一允许调用 Provider 的组件。业务 Router / Service 不得直连 OpenAI SDK 或第三方 SDK。

### Operation Policy

| Operation | route_tier | 要点 |
|---|---|---|
| `ai_analysis` | `low_cost` | Evidence Gate、confirmed、Idempotency-Key、额度预占 |
| `executive_report` | `high_quality` | 需成功分析等策略；生成 ReportVersion；**不自动审批** |

金额用 **Decimal**，禁止 float。

### Provider 与默认模式

- 默认：`LLM_PROVIDER_MODE=stub` / `effective_mode=stub`
- 可选：`openrouter` / `fallback_chain`
- Fallback 固定串行：OpenRouter → NVIDIA → Gemini → Local Qwen
- 熔断状态在 PostgreSQL（`llm_provider_circuit_state`）
- 尝试明细：`llm_provider_attempts`
- 账本：`llm_usage_ledger` + `llm_quota_buckets`
- 分析结果：`ai_analysis_results`

### AI Runtime 持久化

表：`ai_runtime_settings`（单例）

- 字段：mode / kill_switch / version / actor 等
- **Secret 永不入库、永不进 API 响应**
- API：`GET/PATCH /api/v1/admin/ai-runtime`（`security.manage`）
- InMemory 后端对该管理能力 **503 fail-closed**
- Kill Switch 强制 stub；乐观锁 `expected_version` 冲突 → 409
- 启用真实 LLM 需二次确认文案

## 第七章 董事会报告与 Approval

### Report / ReportVersion

- `reports`：当前有效报告实体（与 task 关联）
- `report_versions`：不可变快照；修订产生新版本，不覆盖旧正文
- 报告生成成功返回 task_id / report_id / report_version_id
- 前端可「提交审批」→ `/approval?approval_id=`

### 审批状态机（企业能力）

```text
generated
→ submit → pending_approval
→ approve → approved
→ reject → rejected
→ revise → revised（新 ReportVersion）
→ resubmit → pending_approval
```

### 权限边界

| 动作 | 权限 | 典型结果 |
|---|---|---|
| submit | `approval.submit` | 201 `pending_approval` |
| list 队列 | `approval.review` | manager/admin |
| approve / reject | `approval.admin` | employee → **403** |
| revise / resubmit | submit + owner 或 admin | ownership 检查 |
| detail | review 或 owner | employee 可读自己的 |

并发：PostgreSQL 行锁 + partial unique（每 task 至多一个 pending）。

History：`approval_events` append-only；Audit：`audit_logs` 独立安全事实。
