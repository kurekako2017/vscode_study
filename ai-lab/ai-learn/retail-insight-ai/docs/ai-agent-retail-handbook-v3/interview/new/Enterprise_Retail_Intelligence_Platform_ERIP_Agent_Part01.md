### 面试官可能的提问

ERIPとは何ですか。

### 推荐回答

```text
ERIP、
Enterprise Retail Intelligence Platformは、
大手流通グループ向けの
AI経営分析プラットフォームです。

LangChain と LangGraph を中核とした
エンタープライズ AI エージェント基盤 です。

経営企画部門が保有する社内文書を一元管理し、
LangChainによるRAGで分析根拠を取得し、
LangGraphのエージェントワークフローで経営分析を実施します。

企業向けAI Agentシステムです。
```

### 回答重点

- 是什么系统
- 解决什么业务

## 1.2 なぜERIPを開発したのですか

### 推荐回答

```text
従来の経営分析では、
担当者が売上データ、在庫データ、
会議資料、Excel資料などを個別に確認し、
分析レポートを作成していました。

資料が複数の場所に分散しているため、
情報収集だけでも多くの時間が必要でした。

また、
分析結果の根拠を後から確認することも
容易ではありませんでした。

そこで、
社内文書を一元管理し、
RAGで分析根拠を取得し、
エージェントワークフローで分析とレポート作成を進め、
承認と監査まで含めて効率化するために、
ERIPを開発しました。
```

### 追问：何が一番改善されましたか

```text
資料検索、分析、レポート作成までの時間を
大幅に短縮できた点です。

また、
分析結果の根拠となる社内文書も
同時に提示できるため、
説明責任を担保できる点も
大きな改善点です。
```

## 1.4 どのような課題を解決しましたか

### 推荐回答

```text
主に三つあります。

一つ目は、
社内文書が複数の場所に分散していることです。

二つ目は、
分析レポート作成に時間が掛かることです。

三つ目は、
分析結果の根拠が残りにくいことです。

ERIPでは、
文書管理、RAG、エージェントワークフロー、
承認、監査までを一元管理することで、
これらの課題を解決しました。
```

### 追问：一番大きい価値は何ですか

```text
AIが回答することだけではありません。

AIが社内文書を根拠として分析し、
利用者が分析結果と根拠文書を
同時に確認できることです。

この点が、
企業業務で利用する上で
最も重要な価値だと考えています。
```

## 1.5 なぜChatGPTだけでは不十分ですか

### 推荐回答

```text
ChatGPTは非常に優れた汎用生成AIですが、
企業内部文書を業務ルールに沿って
利用する仕組みは別途必要です。

また、
企業業務では、
回答の根拠、アクセス権限、
承認、監査、利用履歴管理も必要です。

ERIPでは、
LangChainのRAG、
LangGraphのワークフロー、
JWT/RBAC、承認、監査を組み合わせ、
企業業務向けAI Agentとして構築しました。
```

### 回答原则

不要说：

```text
ChatGPTは使えません。
```

应说明：

```text
ChatGPTは汎用AI、
ERIPは企業業務向けAI Agent Platformです。
```

## 1.6 ChatGPTとの違い

| 比较项目 | ChatGPT                  | ERIP                                                        |
| -------- | ------------------------ | ----------------------------------------------------------- |
| 主要用途 | 汎用対話・生成           | 企業経営分析 Agent                                          |
| 数据来源 | 一般知識・入力内容       | 社内文書                                                    |
| 根据信息 | 必ずしも提示されない     | LangChain RAG の根拠提示                                    |
| 处理形态 | 単発対話中心             | LangGraph の多段階 ワークフロー                             |
| 权限控制 | 业务系统侧需另行实现     | JWT（JSON Web トークン） / RBAC（ロールベースアクセス制御） |
| 审批     | 标准对话功能中无业务审批 | 承認ワークフロー（承認 ワークフロー）                       |
| 审计     | 需要另行构建             | 監査ログ（監査 Log）                                        |
| 文档管理 | 不属于核心业务功能       | Enterprise 文書管理（文書 Management）                      |
| 报告生成 | 通用文本生成             | 取締役会向けレポート + Version                              |

### 总结回答

```text
ChatGPTは汎用AIです。

ERIPは、
社内文書、LangChain RAG、
LangGraph ワークフロー、
権限、承認、監査を統合した
企業向けAI Agentプラットフォームです。

用途と責任範囲が異なります。
```

## 2.1 ERIP 全体アーキテクチャ

## 面接官

ERIP の全体アーキテクチャを説明してください。

## 回答

```text
ERIP の全体像は次の通りです。

利用者
  ↓
React フロントエンド
  ↓
FastAPI API
  ↓
JWT 認証（Authentication） / RBAC 認可（Authorization）
  ↓
Business サービス層
  ↓
文書管理 / 検索処理 / Analysis
  ↓
LangChain（AI コンポーネント統合）
  ↓
LangGraph エージェントワークフロー
  ↓
LLM ゲートウェイ
  ↓
PostgreSQL / pgvector
  ↓
承認 / 監査 / レポート

React は操作と結果表示、
FastAPI は企業 API と業務入口、
LangChain は LLM・プロンプト（Prompt）・リトリーバー（Retriever）・RAG など
AI 処理部品の統合、
LangGraph は状態付きの多段階 エージェントワークフロー、
PostgreSQL / pgvector は業務データ・文書・ベクトルと状態の永続化、
承認 は AI 生成結果の人確認、
監査 は操作と責任の追跡を担当します。
```

## 追問

どこが AI Agent の中核ですか。

## 回答

```text
中核は LangChain と LangGraph です。

LangChain で根拠取得と LLM 利用を組み立て、
LangGraph で分析の順序・分岐・状態を制御します。

その前後に、
権限、文書管理、承認、監査 を付けて
企業システムとして成立させています。
```

## Point

- 先画整图，再解释各层
- 中核是 LangChain + LangGraph，不是只讲 FastAPI
- 承認 / 監査 要出现在架构末端
  【学习提示】

架构口述顺序固定为：入口 → 权限 → 业务 → LangChain → LangGraph → 数据 → 治理。

## 4.3 3分钟架构说明

```text
ERIP の目的は、
経営企画が社内文書に基づき
説明可能な経営分析を行うことです。

全体は、
フロントエンド、API、権限、業務サービス、
LangChain、LangGraph、
データ、承認、監査 で構成されます。

LangChain は AI コンポーネント層です。
プロンプト、リトリーバー、RAG、LLM 接続を統合し、
一歩の AI 処理を安定して提供します。

LangGraph は エージェントワークフロー 層です。
START から route、kpi、research、report、END までを

これにより、
単なる一問一答 RAG ではなく、
多段階の分析業務を実行できます。

さらに、
JWT/RBAC で権限を貫き、
PostgreSQL で業務事実を保存し、
承認 で人の責任分界を残し、
監査 で追跡可能にします。

私は、
FastAPI、React、PostgreSQL、
LangChain RAG、LangGraph ワークフロー、
JWT/RBAC、承認、監査 を担当しました。
```

## 4.5 LangChain / LangGraph 30秒比较

```text
LangChain は AI コンポーネント を構成する フレームワーク、

LangGraph で全体 ワークフロー を制御します。

```
