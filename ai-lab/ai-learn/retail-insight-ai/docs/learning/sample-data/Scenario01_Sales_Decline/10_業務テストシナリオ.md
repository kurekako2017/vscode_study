# 10_業務テストシナリオ

# Scenario01_Sales_Decline

共通シナリオ: 2026年6月 / 関東地区飲料分類売上下降分析

- 対象企業: 日本大型零售企業
- 正式システム: Enterprise Retail Intelligence Platform（ERIP）
- 部門: 经营企划部
- 業務背景: 関東地区の飲料販売が前年比・前月比ともに低下し、原因の切り分けと改善提案が必要
- 共通因果: 売上下降 → 在庫欠品 → 促販効果不振 → 競合値下げ → Analysis → 改善提案
- 共通商品: 炭酸飲料 / 茶飲料 / ミネラルウォーター / 無糖飲料
- 共通地域: 東京 / 神奈川 / 千葉 / 埼玉
- 共通結論の方向性: 供給改善、棚割り再設計、販促見直し、競合対策、KPIモニタリング

| 項目 | 内容 |
|---|---|

| 用途 | Documents / RAG / Analysis / Approval の業務導線確認 |

## シナリオ目的

このシナリオは、10 章の業務資料を実際にアップロードし、ERIP の各画面でどのように流れるかを確認するためのテストである。
文書登録から RAG、Analysis、Approval までを同じケースID体系で結び、学習者が実務操作を追えるようにする。

## Step 1 Documents

1. Documents を開く。
2. `01_関東地域飲料売上分析.md` をアップロードする。
3. 文書一覧に表示されることを確認する。
4. `Import` を実行する。
5. `Chunk` を実行し、`document_id` を控える。
6. `02_関東地域在庫レポート.md` から `06_KPI月次報告.md` まで順に登録する。
7. すべての文書でタイトル・状態・更新日時を確認する。
8. `Archive` は今回は実行せず、元資料として保持する。

## Step 2 RAG

1. RAG 画面を開く。
2. `RAG-BIZ-001` を入力する。
3. Citation に `01_関東地域飲料売上分析` と `02_関東地域在庫レポート` が出ることを確認する。
4. Chunk に売上総括と欠品率の説明が表示されることを確認する。
5. `RAG-BIZ-010` から `RAG-BIZ-030` まで順に検索し、各入力が対応する文書を参照することを確認する。

## Step 3 Analysis

1. Analysis 画面を開く。
2. `TASK-BIZ-001` を入力する。
3. SSE による進捗表示を確認する。
4. Workflow が売上低下、在庫欠品、販促不振、競合価格の順で整理されることを確認する。
5. Report が生成されたら、参照文書と整合しているか確認する。
6. `TASK-BIZ-020` まで順に実施し、各報告が同じシナリオ背景を保っていることを確認する。

## Step 4 Approval

1. Approval 画面を開く。
2. `APR-BIZ-001` を表示し、承認コメントを確認する。
3. `approval_id` が採番されることを確認する。
4. `report_version` が Analysis の結果と一致することを確認する。
5. 修正依頼・却下・承認の3種類をそれぞれ確認する。
6. `APR-BIZ-020` まで順に確認し、改善計画の承認まで一連の流れを追う。

## 期待される学習結果

- Documents は入力データの入口である。
- RAG は文書から根拠を引く入口である。
- Analysis は業務判断のための整理工程である。
- Approval は施策実行の可否を決める工程である。
- 4 つの画面が同じ業務背景でつながることで、ERIP の全体像を学べる。

## 実行チェックリスト

| 確認項目 | 期待結果 |
|---|---|
| Documents 登録 | 10 文書が一覧に出る |
| RAG Citation | 対応文書が表示される |
| Analysis SSE | 進捗が段階的に出る |
| Report | 売上・在庫・販促・競合が統合される |
| Approval | 承認/修正依頼/却下が確認できる |

## 補足

このシナリオは Scenario01 のみを対象にし、他のシナリオは作成しない。
各文書の数値は相互参照できるように統一してある。
学習時は必ず同じ背景を使い、別の売場や別の月に話を飛ばさないこと。
ERIP の学習面では、操作順とデータ整合性の両方を確認することが重要である。
