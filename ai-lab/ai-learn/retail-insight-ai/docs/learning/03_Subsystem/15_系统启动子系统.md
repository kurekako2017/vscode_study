# 四、Uvicorn 的职责

Uvicorn 是 **ASGI Server**。

职责：

- 启动 Python 应用
- 接收 HTTP 请求
- 调用 FastAPI
- 返回 HTTP Response

整体关系：

```text
Browser
    │
HTTP Request
    │
Uvicorn
    │
FastAPI
```

> **Uvicorn 负责网络通信，不负责业务逻辑。**

# 六、Router 注册

`main.py` 中通常会注册：

```text
Health API
Tasks API
Documents API

Security API
```

关系如下：

```text
FastAPI
    │

    │
各业务 API
```

这样每个模块保持独立。

---

# 七、Dependency Injection（依赖注入）

FastAPI 使用依赖注入管理对象。

例如：

```text
Router
    │
TaskService
    │
Repository
```

Router 不需要自己创建对象。

框架负责：

- 创建对象
- 生命周期管理
- 注入依赖

优点：

- 解耦
- 易测试
- 易维护

---

# 八、一次 HTTP 请求

一次典型请求：

```text
Browser
    │
HTTP Request
    │
Uvicorn
    │
FastAPI
    │
Router
    │
Service
    │
Repository
    │
Workflow
    │
HTTP Response
```

如果是：

```text
POST /api/tasks
```

还会继续：

```text
BackgroundTasks
    │
TaskService.run_task()
    │
AnalysisWorkflow.stream()
```

因此：

Request 与 Background 生命周期是分开的。

# 十、企业为什么这样设计（Why）

采用分层架构：

```text
Uvicorn
    │
FastAPI
    │
Router
    │
Service
    │
Repository
    │
Workflow
```

每层职责：

| 层         | 职责          |
| ---------- | ------------- |
| Uvicorn    | Web Server    |
| FastAPI    | Web Framework |
| Router     | API 接口      |
| Service    | 业务逻辑      |
| Repository | 数据访问      |
| Workflow   | AI 分析流程   |

这样：

- 易维护
- 易测试
- 易扩展
- 企业项目标准分层

# 十三、面试回答

如果面试官问：

> 系统是如何启动的？

可以回答：

> 项目采用 Uvicorn 作为 ASGI Server，启动 FastAPI 应用。`main.py` 创建应用实例并注册所有 Router，通过依赖注入连接 Service、Repository 和 Workflow。对于 AI 分析任务，HTTP 请求返回 202 后，由 BackgroundTasks 启动后台 Workflow，实现 Web 请求与 AI Workflow 解耦。
