# 一、子系统定位

系统启动子系统（Application Startup Subsystem）负责整个应用的启动与初始化。

主要职责：

- 启动 Uvicorn
- 创建 FastAPI App
- 注册所有 Router
- 初始化系统组件
- 接收 HTTP 请求
- 将请求分发到业务模块

一句话：

> **main.py 是整个 Retail Insight AI 的总入口。**

# 四、关键类与关键函数 ⭐

## FastAPI()

作用：

创建整个 Web Application。

可以理解为：

整个系统的大门。

---

## include_router()

作用：

把各个模块注册到系统。

例如：

```python
app.include_router(tasks.router)
app.include_router(documents.router)
app.include_router(approvals.router)
```

没有注册：

接口就不存在。

---

## BackgroundTasks

作用：

启动后台任务。

例如：

```text
POST /api/tasks
```

返回：

```text
202 Accepted
```

之后：

后台：

继续执行：

```
run_task()
```

---

## lifespan()

作用：

管理：

Application Startup

↓

Application Shutdown

生命周期。

# 十七、面试回答（中文）⭐⭐

面试官：

> Retail Insight AI 是如何启动的？

回答：

> 项目使用 Uvicorn 作为 ASGI Server，通过 main.py 创建 FastAPI 应用，并注册各业务 Router。HTTP 请求首先进入 Router，再调用 Service 和 Repository。对于 AI 分析任务，接口返回 202 Accepted 后，通过 BackgroundTasks 启动 AnalysisWorkflow.stream()，实现请求处理与 AI Workflow 的解耦，同时结合 Learning Trace 和 EventPublisher 完成后台执行与实时状态更新。

---

# 十八、面试回答（日语）⭐⭐

面接官：

> システムはどのように起動しますか。

回答例：

> Retail Insight AI は Uvicorn を ASGI サーバーとして使用し、main.py で FastAPI アプリケーションを生成しています。main.py では各 Router を登録し、HTTP リクエストを Service、Repository、Workflow に振り分けます。AI 分析処理は POST /api/tasks 実行後に 202 Accepted を返し、その後 BackgroundTasks により AnalysisWorkflow.stream() がバックグラウンドで実行されます。これにより、HTTP リクエストと AI Workflow を疎結合にし、Learning Trace と EventPublisher を利用してリアルタイムに処理状況を追跡できる構成になっています。
