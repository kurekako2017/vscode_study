# 一、子系统定位

事件通信子系统（Event Communication Subsystem）负责：

- 发布事件（Publish）
- 广播任务状态
- 通知前端
- 解耦业务模块

一句话：

> **Workflow 负责处理业务，EventPublisher 负责通知世界。**

# 十五、企业设计意义 ⭐

企业项目：

不会：

直接：

```
Workflow

↓

Frontend
```

而是：

```
Workflow

↓

EventPublisher

↓

Subscriber

↓

Frontend
```

好处：

- 解耦
- 可维护
- 可扩展
- 易测试
- 支持多个消费者

这是典型的：

**Event Driven Architecture（EDA）**

---

# 十六、面试回答

如果面试官问：

> 为什么使用 EventPublisher？

可以回答：

> Retail Insight AI 将事件发布从 Workflow 中独立出来。Workflow 只负责业务处理，EventPublisher 统一负责广播事件，再由 SSE 推送到前端。这样 Workflow 不依赖任何 UI 或通信方式，未来可以扩展到 Kafka、RabbitMQ、Redis Pub/Sub 等消息系统，而无需修改业务代码。
