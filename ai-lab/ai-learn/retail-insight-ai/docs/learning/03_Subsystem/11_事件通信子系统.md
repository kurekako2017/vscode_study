# 三、EventPublisher

职责：

-   创建事件
-   发布事件
-   解耦业务层
-   不直接依赖前端

Workflow 只需要：

``` python
publish(...)
```

无需知道事件最终发送给谁。

------------------------------------------------------------------------

# 四、事件生命周期

``` text
queued
   │
running
   │
progress
   │
completed
```

每次状态变化都会发布对应事件。

------------------------------------------------------------------------

# 五、SSE

SSE（Server-Sent Events）负责：

``` text
EventPublisher
      │
HTTP 长连接
      │
Browser
```

特点：

-   服务端主动推送
-   浏览器自动接收
-   无需轮询

------------------------------------------------------------------------

# 六、Workflow 与事件通信

``` text
Route
   │
publish(progress)
   │
KPI
   │
publish(progress)
   │
Research
   │
publish(progress)
   │
Report
   │
publish(completed)
```

浏览器因此可以实时更新任务状态。

# 十一、面试回答

项目采用 EventPublisher + SSE 架构，将业务处理与消息通知解耦。Workflow
只负责发布事件，EventPublisher 负责广播，SSE
负责推送浏览器，便于未来扩展到 RabbitMQ、Kafka 等消息系统。
