# 一、子系统定位

任务持久化子系统（Task Persistence Subsystem）负责整个项目的任务数据管理。

职责包括：

- 创建任务
- 保存任务状态
- 查询任务
- 更新任务
- 为 AI Workflow 提供状态持久化

一句话：

> **Repository 是整个业务层访问数据的唯一入口。**

---

# 二、源码目录结构 ⭐

源码位置：

```text
backend/
└── app/
    └── repositories/
        ├── interfaces/
        │      └── task_repository.py
        │
        ├── implementations/
        │      └── in_memory/
        │             └── task_repository.py
        │
        └── report_repository.py
```

职责：

- interfaces/

  - 定义 Repository 接口
- implementations/

  - Repository 具体实现

当前项目：

采用：

```text
InMemory Repository
```

未来可以替换：

```text
PostgreSQL Repository
```

无需修改 Service。

# 四、关键类与关键函数 ⭐

## TaskRepository

整个任务持久化核心。

---

### create()

作用：

创建任务。

调用位置：

```text
TaskService.create_task()
```

创建：

```text
Task

↓

queued
```

---

### save()

作用：

保存任务状态。

调用位置：

```text
TaskService.run_task()
```

例如：

```text
queued

↓

running

↓

completed
```

每一次状态变化都会调用。

---

### get()

作用：

读取任务。

例如：

```text
GET /api/tasks/{task_id}
```

用于：

查询当前任务状态。

---

### list()

作用：

返回任务列表。

通常用于：

```text
Dashboard
```

---

# 九、为什么采用 Repository Pattern（Why）

如果：

```text
TaskService

↓

SQL
```

以后数据库切换：

所有代码都要修改。

采用：

```text
TaskService

↓

Repository

↓

Database
```

以后：

```text
SQLite

↓

PostgreSQL

↓

MongoDB
```

Service 不需要修改。

这是企业开发最常见的设计模式。

# 十三、面试回答

如果面试官问：

> 为什么采用 Repository Pattern？

可以回答：

> Retail Insight AI 将数据访问统一封装到 Repository。TaskService 不依赖具体数据库实现，因此可以从 InMemory Repository 平滑切换到 PostgreSQL，而无需修改业务逻辑。这种设计提高了系统的可维护性、可测试性和可扩展性，是企业项目中非常常见的架构模式。
